# h5 step H5-1b: ray dataset, sampler and on-the-fly targets

torch `Dataset` for the ray decoders, no model yet. Branch `h5`. Nothing in `src/`, `phd_work/`,
`csgbox` or `dexelize` was changed. The only edit to an existing file is `h5/rays.py`, where the
`DexelFile` axis conversion moved into `rayhits_from_arrays` so the dataset can read the file once.
No dependency was added.

## Interfaces

### `h5/data.py`

- `RayShapeDataset(split, target, n_rays=1024, n_points=10000, noise=0.001, seed=None, root=DATA_ROOT)`:
  one item per line of `csg/{split}.lst`. `target` is one of `hits_8`, `hits_16`, `occfrac_128`,
  `tsdf_128`, `binary_128`.
  - `inputs` (n_points, 3) float32: points drawn without replacement from `pointcloud.npz`,
    plus Gaussian noise with sigma `noise`.
  - `ray_axis` (n_rays,) int64, `ray_index` (n_rays,) int64 (`r = i_col + N i_row`),
    `ray_origin_uv` (n_rays, 2) float32 (cell centre `lo + (k + 1/2) h` on the two perpendicular
    axes, ordered (col, row)).
  - hits targets: `hits_s` (n_rays, 4K) float32 in cell units, `s = (t - BOX_LO) / h` with
    `h = cell_size(128)`; `hits_mask` (n_rays, 2K) bool. K = 2 for `hits_8`, K = 4 for `hits_16`.
    A masked-out slot has `t = 0`, so its `s` is ignored.
  - dense targets: `y` (n_rays, 128): float32 for `occfrac_128` and `tsdf_128`, bool for
    `binary_128`; `informative` (n_rays, 128) bool.
  - Only the requested target is built. The dexel file is read once per item (`dexio.read`).
- Sampler (per item): each ray is, with probability 1/2, uniform over all 3·128² rays, and otherwise
  uniform over the rays with at least 2 hits (axes pooled). A ray can be drawn twice.
- Randomness: one `numpy.random.Generator` per item. With `seed` given, it is
  `default_rng(SeedSequence([seed, index]))`, so a fixed seed gives identical items. With
  `seed=None` it is seeded from `torch.initial_seed()`. A DataLoader worker sets that per worker and
  per epoch, so items are reproducible only when `seed` is given.
- `fixed_val_rays(shape_index, n=4096, split="val")`: the same sampler with `default_rng(shape_index)`,
  so validation always sees the same rays. Returns `(ray_axis, ray_index, ray_origin_uv)`.
- `informative(y, target)`:
  - `occfrac_128`: `0 < y < 1`.
  - `binary_128`: cells next to a change of occupancy, on both sides.
  - `tsdf_128`: `|y| < 2.5 h`, computed against `float32(2.5 h)` so that clamped values are excluded.
  - The rule is applied to the stored float32 values.
- Points are numpy, not ConvONet's `PointCloudField`. That field adds noise from the global RNG,
  and the dataset needs the explicit Generator.

### `h5/rays.py` (changed)

- `rayhits_from_arrays(arrays)`: one `dexio` axis to a float64 `RayHits`. `load_axis_rayhits`
  uses it, and its behaviour is unchanged.

## Dense weight

`h5/scripts/dense_weight.py`: 200 train shapes chosen by `Generator(PCG64(0))` from `train.lst`,
the training sampler with `seed=0`. `w = (1 - f) / f` makes the informative cells half of the loss.

| target | informative cells | total cells | f (pooled) | mean of per-shape f | w = (1-f)/f |
|---|---|---|---|---|---|
| occfrac_128 | 400099 | 26214400 | 0.0153 | 0.0153 | 64.520 |
| tsdf_128 | 1795522 | 26214400 | 0.0685 | 0.0685 | 13.600 |
| binary_128 | 753839 | 26214400 | 0.0288 | 0.0288 | 33.775 |

The weights are 64.5, 13.6 and 33.8, which are very large. The informative cells are rare, so most of
the loss weight goes to a few cells. The spec asks for this rule, and the table is reported as
computed. Whether the weights are capped is a decision for the training step (H5-2 or later), not
for this one.

### Timing (test f)

Single process, batch of one item, after one warm-up item. Median of 32 items per target, 20 test
shapes, 1024 rays, 10000 points, `noise = 0.001`:

| target | median per item | DataLoader workers to keep 32 items under 0.15 s |
|---|---|---|
| hits_8 | 4.91 ms | 2 |
| hits_16 | 4.73 ms | 2 |
| occfrac_128 | 4.96 ms | 2 |
| tsdf_128 | 7.53 ms | 2 |
| binary_128 | 6.56 ms | 2 |

Median `dexels_128.npz` size: **1.36 MB** per shape. The workers figure is `ceil(32 · median / 0.15)`,
so two workers suffice for every target on this machine, with the costs of the file reads
included.

## Notes and limits

- The mixture sampler can draw the same ray twice. `subset_rays` allows that, so the targets are
  consistent.
- `seed=None` gives items that are not reproducible across runs. Use a seed for any run that must
  be repeated.
- The dense target informative rule depends on the value stored in float32. A cell whose float64
  value is just below 1 can be stored as 1.0 and then counted as uninformative.
