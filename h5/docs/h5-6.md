# H5-6: diagnostics, metric fix, memorisation probe Q0

Scope: `h5/` only. `src/`, `phd_work/`, csgbox and dexelize are unchanged.

## 1. Diagnostics (`h5/eval_rays.py`)

- `nearest_same_type(gt, dec)`: for every GT hit, |t| to the nearest decoded hit of the same type (enter/exit)
  on the same ray; inf if none. Independent of the delta and of the csgbox greedy matching.
- `thin_endpoints(gt, h)`: a GT hit is *thin* if it is an endpoint of a GT interval (material or gap) shorter
  than `GEN_THIN_CELLS h` = 4h. Its bin is the L/h bin of its shorter adjacent thin interval (`csgbox.ceilings.thin_bins`).
  All other GT hits are *ordinary*.
- `hit_diagnostics(gt, dec, h, deltas)`: per axis, additive counts and histograms for ordinary hits and per thin bin:
  histogram of the distance (0.6 % log bins), counts within each delta, and GT hits matched at each delta
  (the csgbox greedy match, so recall is the same definition as F1).
- `evaluate_axis_diag` = csgbox `evaluate_axis` (unchanged) plus `diag`. Used in `score_grid`, `score_points`
  and the ceilings of `pilot_report.py`.
- `aggregate()` adds `dec_gt_ratio`, `m_comparable` and `diag` (ordinary n, median, p90, within-delta fractions,
  recall per delta; the same per thin bin). The median and p90 are read from histograms (bin centre, error < 0.6 %).
- `to_markdown()` adds the "Per-hit diagnostics" table.

Note: `within` is the nearest-distance fraction. Recall is the greedy-match fraction. The two differ by design.

## 2. Metric fix

- Every summary carries `dec_gt_ratio` (decoded / GT hits). `m_comparable` is False when the ratio is outside
  `RATIO_BAND = (0.8, 1.25)`.
- `to_markdown` prints M, precision and decoded/GT next to each other and marks M **not comparable** when the
  ratio is outside the band.
- `pilot_report.py` does the same in the eval log lines, the P1 and P2 lines, the M table, the ceilings line and
  the P2 table. It prints a warning when any M used by the decision is not comparable. **The verdict logic is
  unchanged** (the mark is a warning, not a rule).
- `OCC_SNAP_GRID` = (1e-3, 1e-2, 0.03, 0.1, 0.2, 0.3, 0.4, 0.45). The 1e-3 of H5-5 is kept, so settings already
  selected in the pilot remain in the grid. Changing the grid changes the validation grid of occfrac_128 runs
  started after this commit.

## 3. Q0 runner

Question: can the hits_8 and points_strong decoders memorise 32 training shapes (all rays) at all?

Settings: `train_subset 32` (seed 0), `eval_on_train true`, `batch_size 32`, `max_it 30000`, `val_every 5000`.
Each sample is one shape, so one iteration uses all 32 shapes.

### How to start Q0

```
cd ~/PhD/convonet
h5/scripts/q0.sh            # full probe, about 3 h
```

Interrupting and running the same command again resumes each training run from `model_last.pt`. A finished run is
skipped. Evaluations that already have a result are skipped too. If a run crashed before its first validation,
the script stops and asks you to move that directory.

Dry run (tiny numbers, scratch directory, not the probe):

```
Q0_DRY_ROOT=/some/scratch/dir h5/scripts/q0.sh --dry-run
```

### Rule (fixed before the run)

Let final = 30000 and prev = 20000.

- **REACHABLE** if both runs reach recall(0.002) >= 0.8 on ordinary hits at some iteration <= 30000.
- **NOT REACHABLE** if both runs have recall(0.002) < 0.5 at 30000 **and** the median distance of ordinary hits
  improves by < 10 % from 20000 to 30000 (per run).
- **UNCLEAR** otherwise.

REACHABLE is checked first. A median that is inf at prev and finite at final counts as improvement. A median that
gets worse counts as no improvement.

### File layout

Outside the repository (`~/PhD/runs/h5_q0/`):

```
                    model_it{5000..30000}.pt and .json, model_last.pt, model_best.pt

```

```

```

### Expected duration

About 3 h (the estimate given for this step, not measured on this machine). Training is 30000 iterations per run.
Validation runs on the 32 shapes with all rays every 5000 iterations. The evaluation adds one pass per checkpoint
(6 per run, all rays of 32 shapes).

## 6. Extension: learning-rate drop and occfrac_128 (H5-6c)

**Train.** `train.py` reads an optional config key `lr_steps`: a list of `[iteration, lr]`. From iteration `k` (1-based, as logged) on, the learning rate is `lr`; the value is computed from the iteration counter at every step, so a resumed run gets the same rate as an uninterrupted one. The rate is logged in every `log.jsonl` record (`lr`). Each resume writes `config_resumed_at_{iteration}.json` (the config of that resume; `config.json` keeps the first one). Without `lr_steps` the rate is constant, as before.

**Run.** `h5/scripts/q0.sh --extend`: first the v1 runs to 30000 if they are missing, then Q0_points_strong and Q0_hits_8 resumed to 60000 with `lr_steps [[50000, 1.0e-5]]` (`1.0e-5`: YAML reads `1e-5` as a string), then Q0_occfrac_128 from scratch with the same settings and schedule. Every checkpoint at 5000..60000 without a result is evaluated (32 shapes, all rays); results already written are kept.

**Rules.** v1 (verdict at 30000, points_strong and hits_8) is unchanged. v2 (fixed before the extension run, at 60000, points_strong and hits_8 only): REACHABLE if both reach ordinary recall(0.002) >= 0.8 at any iteration <= 60000; NOT REACHABLE IN BUDGET if both are < 0.6 at 60000; UNCLEAR otherwise. occfrac_128 is described but not in any rule.

**Descriptive (no rule).** Ordinary recall and median at 50000, 55000 and 60000 per run; a table at 60000 of thin-bin recall(0.002) and median per L/h bin for hits_8, occfrac_128 and points_strong, with decoded/GT and precision.

**Duration.** Not measured. The extension adds 30000 iterations to each of the two v1 runs and trains occfrac_128 for 60000 iterations, plus 24 evaluations of 32 shapes with all rays. Expect it to take longer than the v1 chain.

Dry run: `Q0_DRY_ROOT=<scratch> h5/scripts/q0.sh --extend --dry-run` (exit 0; v1 to 40, extension to 80, drop at 60, validation every 10, 4 shapes, batch 2). The learning rate in the dry run changes from 1e-4 to 1e-5 at iteration 60 in all three runs (checked in `log.jsonl`). End of `chain.log`:
