# H5-K2-1a: ray-interval query sampler for the point decoder

Status: sampler and tests only. `train.py`, `eval_rays.py` and the scripts are unchanged, so no run uses the new
targets yet.

## What was added (`h5/data.py`)

- `RAYINT_TARGETS = ("points_rayint_a", "points_rayint_b")`, `RAYINT_N_RAYS = 512`, `RAYINT_MIN_SEGMENT = 1e-9`.
- `rayint_segments(axes, start_inside, g)`: the segments of the sampled rays. Each ray's box `[BOX_LO, BOX_HI]` is cut
  at its hits `t_0 < ... < t_{k-1}`, which gives k + 1 segments. Occupancy alternates, starting outside. The function
  asserts that `start_inside` is 0 on every sampled ray, reading it from `dexels_128.npz` because `RayHits` does not
  carry it. I also checked 40 train shapes (every 250th), all three axes: `start_inside` is 0 everywhere and every `t` is inside
  the box. Segments shorter than 1e-9 are dropped after the occupancy is assigned, so the alternation is unaffected.
- `build_rayint_item(shape_dir, rng, target, n_points, noise, n_query=N_QUERY, n_rays=512)` returns the same keys as
  `build_point_item`, with `from_surface` all False. The draws from `rng` come in this order:
  1. the encoder input, exactly as in `build_point_item` (a test checks the arrays are equal for the same seed);
  2. `sample_global_rays(ray_counts(axes), rng, n_rays)`;
  3. `n_query` segments with replacement: uniform over all segments for variant a, with probability length / total
     length for variant b;
  4. `t` uniform in each chosen segment.

  The point is the cell centre from `ray_fields` on the two transverse axes ((y, z) for x-rays, (x, z) for y-rays,
  (x, y) for z-rays) and `t` on the ray axis. The output is float32.
- `PointShapeDataset` accepts both targets and dispatches to `build_rayint_item`. `build_point_item` is unchanged.
- `_rayint_sample` is the same function but also returns the rays, segments and chosen segment of every point, for the
  tests.

## Tests (`h5/tests/test_rayint.py`, 11 tests)

The 5 train shapes are chosen with `Generator(PCG64(0))`: 06367, 05110, 02697, 03078 and 08502.

    .venv/bin/python -m pytest h5/tests/test_rayint.py -q -s
    11 passed

- a. Shapes, dtypes and keys are as documented, and every query point is inside the box (both variants).
- b. Agreement with the analytic test `eval_points(from_json(tree.json), query)`:
  - points_rayint_a: **0 disagreements** in 5 x 2048 points, 0 points within 1e-6 of a segment end;
  - points_rayint_b: **0 disagreements**, 0 points within 1e-6.
- c. Share of points in segments shorter than h(128), shape 06367, 200 draws per variant: **a 0.0052, b 0.0000**
  (4.4e-5). Variant a is about 120 times b. The test requires a > 5 b. This shape has few such short segments, so
  the absolute share of a is small.
- d. Variant b: the mean occupancy of the points against the exact mean along the same sampled rays (from the interval
  lengths). The largest difference is 0.012 (shape 03078), within the 0.02 tolerance:

  | shape | points | along the rays |
  |---|---|---|
  | 06367 | 0.2397 | 0.2428 |
  | 05110 | 0.1895 | 0.1991 |
  | 02697 | 0.1465 | 0.1570 |
  | 03078 | 0.0840 | 0.0725 |
  | 08502 | 0.1626 | 0.1590 |

- e. The same seed gives identical arrays, from both `build_rayint_item` and `PointShapeDataset`. `build_point_item` on
  train shape 0 with `Generator(PCG64(123))` matches the sha256 recorded before the change, for both point targets.
