# H5-K1-4: the remaining four decoders and the combined K1 report

## Chain (`h5/scripts/k1_4.sh`)

The script copies the style of `k1_1.sh`: resume-safe, `set -euo pipefail`, `ROOT/chain.log`, `--dry-run` in a
scratch directory. Root `~/PhD/runs/k1_4`. It uses the K1-1 settings: full train split, batch 32, 120000 iterations,
`lr_steps [[100000, 1.0e-5]]`, validation every 10000 with the band selection.

- **Order:** tsdf_128, binary_128, hits_8_plane, points_std.
- **Evaluation:** `q0_report.py eval --grid` on model_it{40000,80000,120000} of each run: the first 200 val shapes,
  all rays, every setting of the target's decoding grid with the band selection, and the H5-6 diagnostics (as
  K1-1b). The output is `ROOT/eval/{run}_it{N}_grid.json`.
- **Report:** `k1_1_report.py --root ~/PhD/runs/k1_1 --root ~/PhD/runs/k1_4` writes `h5/results/k1/report.{md,json}`.
  The K1-1 root is only read.

## Combined report (`h5/scripts/k1_1_report.py`, generalised)

- **Roots:** `--root` may be repeated. A run is any directory of a root that has a `config.json`; its target is
  read from that file, and run names must be unique across the roots.
- **Rows:** per checkpoint, the plain evaluation `{run}_it{N}.json` gives the row `{run}`, and the grid evaluation
  `{run}_it{N}_grid.json` gives the row `{run} (grid)`. A run with neither file at a checkpoint is listed as missing.
- **Verdict:** as in K1-1c, at the last checkpoint and delta 0.002, using M (walls and gaps, both ends matched) and
  the per-bin walls+gaps recall. hits_8 is compared with the dense runs in band: occfrac_128 only through its grid
  row; tsdf_128 and binary_128 through the grid row if there is one, otherwise the plain row. Per L/h bin the dense
  value is the better of them. points_std and points_strong are never dense competitors.
- **Thin-bin tables:** a grid row is labelled "grid-selected setting". A plain row that has a grid row and is out of
  band is labelled "out of band, not comparable", as before for occfrac_128.
- **New section "Cost (not evaluated yet)":** the SPEC cost criterion is the same accuracy as the point decoder at
  least 10 times faster. The pilot speed ratios (points_strong N = 512 / method, trained timings,
  `h5/results/pilot/report.md`) are 5.38 for hits_8 and 25.53 for hits_8_plane. So **hits_8_plane** would carry
  the criterion; hits_8 cannot meet it whatever its accuracy. The criterion itself is not computed. The section
  lists the ray-layer values of both variants for orientation only.
- `h5/results/k1_1` is not regenerated and stays as it is. `k1_1.sh` still calls the script with one root.

## Checks

- **K1-1c reproduced:** the report with `--root ~/PhD/runs/k1_1` alone gives the K1-1c verdict field for field:
  undecided (compactness only) against occfrac_128 (grid), M 0.0306 against 0.00338, F1 0.176 against 0.210, the
  same per-bin gains (+0.0376, +0.0340, +0.0224 in [0.125, 1)) and max gain 0.0376. In the markdown only the two
  sentences about points_std and TSDF changed wording, and the cost section was added.
- **Dense selection:** on synthetic labels with all seven runs, the dense runs are occfrac_128 (grid),
  tsdf_128 (grid) and binary_128 (grid). Without grid rows, occfrac_128 is excluded and plain tsdf_128 counts.
- **Dry run** (`K1_DRY_ROOT=<scratch>/k1_4_dry h5/scripts/k1_4.sh --dry-run`, GPU free at the time, 44 s): 4 tiny
  runs, 12 grid evaluations, and the combined report with the real K1-1 root. The K1-1 root has no evaluations at the
  dry-run iterations (10, 20, 30), so the report lists 9 missing rows and the verdict is "not evaluable", which is
  correct.
