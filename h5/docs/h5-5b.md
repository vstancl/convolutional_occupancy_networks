# h5 step H5-5b: decoding-time measurement (P0) and the pilot runner

Two parts. **A:** the decoding-time measurement P0, run now with untrained models (preliminary). **B:** the
pilot runner (`h5/scripts/pilot.sh`) and its report (`h5/scripts/pilot_report.py`), written and dry-run only.
**The pilot has not been started.** Branch `h5`. Nothing in `src/`, `phd_work/`, `csgbox` or `dexelize` was
changed. No new dependency.

## A. P0: decoding time (`h5/scripts/time_decode.py`)

Result: `h5/results/p0/untrained.md` and `.json` (label "untrained, preliminary").

Per shape (test.lst, first 100; first 5 are warm-up and not timed; medians over the other 95; batch 1, fp32,
RTX 4070). Each timed part is bracketed by `torch.cuda.synchronize`.

- **Encoder**: `model.encode` on the 10000 input points.
- **Decoder**: the network over all 3·128² rays, in chunks (ray decoders: rays per call; points: samples per chunk).
- **Conversion**: the CPU decode to `RayHits` (`decode_by_axis`: `decode_slots` for hits, `decode_occfrac`,
  `decode_binary_array`). For points: the protocol's bisection (it calls the network) and the assembly.
- Chunk size: the fastest of {4096, 16384, 49152} rays for the ray decoders and of {256, 1024, 4096} rays for the
  protocol, measured on the warm-up shapes. The choice is in the JSON.
- Default mode and deterministic mode are both reported (the deterministic total is in the table).
- Counts: sign changes (points), kept slots and decoded hits (ray decoders).

| method | chunk | encoder ms | decoder ms | conversion ms | total ms | total, deterministic ms |
|---|---|---|---|---|---|---|
| hits_8 | 16384 | 5.9 | 115.0 | 19.7 | 140.6 | 152.4 |
| hits_8_plane | 49152 | 5.7 | 1.8 | 18.9 | 26.4 | 28.5 |
| occfrac_128 (for information) | 16384 | 6.1 | 117.8 | 1586.5 | 1711.4 | 1715.8 |
| points_strong N = 64 | 1024 | 5.6 | 90.6 | 0.7 | 96.9 | 102.3 |
| points_strong N = 128 | 1024 | 5.7 | 187.1 | 0.8 | 193.6 | 199.4 |
| points_strong N = 256 | 256 | 5.8 | 377.1 | 1.0 | 383.9 | 399.2 |
| points_strong N = 512 | 256 | 5.8 | 740.5 | 1.3 | 747.7 | 764.2 |

Ratio total(points N) / total(method):

| N | hits_8 | hits_8_plane | occfrac_128 |
|---|---|---|---|
| 64 | 0.69 | 3.66 | 0.06 |
| 128 | 1.38 | 7.32 | 0.11 |
| 256 | 2.73 | 14.52 | 0.22 |
| 512 | 5.32 | 28.28 | 0.44 |

**Caveats of the untrained numbers.**

- The untrained point decoder gives a near-constant probability, so at iso 0.5 it has **zero sign changes**. Its
  conversion is therefore the sampling cost only. A trained decoder has one sign change per surface crossing, so
  its conversion time will be larger. The pilot's timing (below) uses trained checkpoints.
- The untrained `hits_8_plane` keeps **zero slots** (its mask logits are negative), so its conversion is the bare
  decoder cost.
- The untrained ray decoders decode about 9·10⁴ hits (hits_8) and about 1.2·10⁷ hits (occfrac, literal rule near
  0.5 everywhere), so the untrained conversion times are not those of trained decoders either.

So the untrained table is a measurement of the machinery and of the sampling cost, not a prediction of trained
timings. The pilot repeats the measurement on the trained P2 checkpoints.

## B. The pilot runner (written and dry-run only)

### How to start the pilot

```sh
cd ~/PhD/convonet && h5/scripts/pilot.sh
```

Do not run it yet (it is the pilot). To check the chain without training, `h5/scripts/pilot.sh --dry-run`, which
uses a scratch directory (`$TMPDIR/h5_pilot_dry_<time>`, or `PILOT_DRY_ROOT`) and small numbers.

The script resumes a run that has a `model_last.pt` (`--resume`). A run directory without `model_last.pt` but with a
`log.jsonl` is an error (train.py refuses to mix runs); remove it by hand after looking at it. The chain stops at
the first failure (`set -e`, `pipefail`).

### What it runs, in order

| step | run | settings |
|---|---|---|
| P1 | `P1_hits_8`, `P1_occfrac_128` | `train_subset` 256, `eval_on_train` true, `max_it` 10000, `val_every` 2500 |
| P2 | `P2_hits_8`, `P2_hits_8_plane`, `P2_occfrac_128`, `P2_points_strong` | full train, `max_it` 20000, `val_every` 5000 |
| eval | every `P2_*/model_it{5000,10000,15000,20000}.pt` (four P2 runs: hits_8, hits_8_plane, occfrac_128, points_strong) | the first 200 shapes of `val.lst`, **all rays**, at the setting in its JSON; plus the GT ceilings of hits_8 and occfrac_128 (at the selected occ_snap of the 20k checkpoint) |
| timing | P2 checkpoints at 20k | `time_decode.py`: hits_8, hits_8_plane and points_strong trained; occfrac_128 untrained (for information); 100 shapes |
| report | `h5/results/pilot/report.md` and `report.json` | the metrics and the verdict |

All outputs of a pilot go to `~/PhD/runs/h5_pilot/` (outside the repository):

```
~/PhD/runs/h5_pilot/
  chain.log                       every step, with its output
  P1_hits_8/  P1_occfrac_128/     train.py run directories (config.json, log.jsonl, val.jsonl,
  P2_hits_8/  P2_occfrac_128/     model_last.pt, model_best.pt, model_it{N}.pt/.json; P1 also train_subset.json)
  P2_points_strong/
  eval/                           {run}_it{N}.json (all-ray summaries), ceilings.json
  timing/                         p2.json, p2.md (time_decode on the 20k checkpoints)
```

The report is written to `h5/results/pilot/` (generated, not committed).

### The metrics and the decision rule (`pilot_report.py`)

- **M** = recall of thin walls and gaps (c ≥ 0.5) at delta 0.002, pooled over the bins L/h < 1.
- **P1 gap** = M(hits_8) − M(occfrac_128) on the train subset (final checkpoint, all rays), at the selected setting.
- **P2 gap** at 5k, 10k, 15k, 20k = the same on the 200 validation shapes, all rays.
- **Point check** = recall of walls and gaps pooled over L/h ∈ [0.25, 1) for `points_strong` at 20k.
- Rules, in order (first match wins):
  1. REDESIGN ENCODER if the point check < 0.3;
  2. STOP if P1 gap ≤ 0.02 and P2 gap (20k) ≤ 0.02;
  3. CONTINUE if P2 gap (20k) ≥ 0.05 and ≥ P2 gap (10k);
  4. UNCLEAR otherwise (extend hits_8 and occfrac_128 to 60k).
- **Speed condition only** (not part of the decision): PASS if hits_8 or hits_8_plane is at least 10× faster than
  points_strong at N = 512 (total per shape, trained timing), else REPORT ONLY.
- **Cost indication** (not a decision; "the full criterion needs the point recall at N < 512"): for hits_8 and
  hits_8_plane at 20k, the speed ratio points N=512 / method (trained timings), and the recall of walls and gaps
  pooled over L/h ≥ 0.25 minus the same for points_strong N = 512 at 20k (validation, all rays).

The report also has the per-bin tables, F1 of all hits, the selected decoding settings, and the GT ceilings of
hits_8 and occfrac_128 on the same shapes and rays.

### Expected duration (estimate, not measured for the pilot)

| part | estimate | basis |
|---|---|---|
| P1 (two runs, 10000 it each, all-ray validation on 256 shapes four times) | 1.2 h to 2 h | 0.21 s/it measured; the all-ray validation is not measured |
| P2 hits_8 and occfrac_128 (20000 it each) | about 2.4 h together | 0.215 and 0.205 s/it measured; four validations of about 10 s and 66 s |
| P2 hits_8_plane (20000 it) | about 70 min | not measured; assumed like hits_8 (same encoder, smaller head) |
| P2 points_strong (20000 it) | about 40 min | 0.105 s/it measured |
| eval (12 checkpoints × 200 shapes × all rays) | 30 min to 1 h | not measured |
| timing (100 shapes; hits_8, hits_8_plane, points, trained; occfrac untrained) | 20 to 40 min | not measured for the whole run; the dry run took 1.5 min for 8 shapes, mostly model loading and the occfrac untrained decode |

Total: **about 6 to 8 hours**. The all-ray validations and the evaluation are the least certain parts: the occfrac
all-ray evaluation of an untrained-like output is slow (see A), and the trained checkpoints may be faster.

### Dry run (done twice)

`pilot.sh --dry-run` ran the whole chain with max_it 40, val_every 20, 4 validation shapes × 256 rays, train_subset
8, eval on 4 shapes, timing on 8 shapes (3 timed). It finished with `CHAIN DONE`. The report was written to
`$TMPDIR/.../pilot_dry/report/report.md`, with the verdict REDESIGN ENCODER only because the point check on 40
iterations is 0 (the point decoder has not learned a surface yet). That is the expected behaviour of the rule at
this size; the numbers are not a result.

Second dry run (with `P2_hits_8_plane`): the first attempt stopped at `P2_hits_8_plane` because the data
layer had no target `hits_8_plane`. Fixed: `TrainSamples` uses the `hits_8` targets for `hits_8_plane` (the head
differs, not the data). The chain then completed (`CHAIN DONE`), with the eval of 6 runs' checkpoints, the timing
(hits_8, hits_8_plane, points trained) and the report with the cost-indication section.

## Choices (not obvious from the spec)

1. **Setting of the timing.** `time_decode.py` uses the setting stored next to a checkpoint (`model_it{N}.json`).
   Without it, it uses the threshold 0.5 (hits) or occ_snap 0.01 (occfrac, for information).
2. **Conversion of the protocol** includes the bisection. The bisection calls the network, so it is part of the
   network's cost; it is reported in the conversion column, separately from the sampling (decoder column).
3. **Evaluation at all rays** in the pilot (the spec's protocol), while the training-time validation uses 4096 fixed
   rays. The F1 of the two are therefore not directly comparable.
4. **Rule 2 uses the literal `≤ 0.02`.** A negative gap (hits_8 worse than occfrac_128) satisfies it.
5. **The report is generated, and is not committed.** Only code, configs and the P0 result are committed.
